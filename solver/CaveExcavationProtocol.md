# 洞室开挖输入协议与回归

2026-10-23，复现算例：`C:/test/rock/洞室开挖工程`。

## 按面开挖

通用 IIJX 使用 KE1、KE2 关联相邻单元；洞室 EXCAIIWL 的解释不同：它把第二列关联读为 ILAY，并在分步计算中比较 `ILAY > IEXCA`，跳过不是本级释放的荷载。洞室导出应写 `KJX KE1 ILAY JD1 JD2 [JD3 JD4] JAT`，ILAY 来自本行 KE1 的负开挖层号。仅洞室开挖导出采用此约定，地应力边界、衬砌等通用 IIJX 不变。

对应本地参考源码：`D:/NASGEWIN64/B_VICSUB/CAE07.f90` 的 EXCAIIWL，`ILAY=JMETBAK(KE,2)`、`IF(ILAY.GT.IEXCA)`。

二维按面计算还直接乘 `CONMAT(MATYPE,58)`，即材料的荷载释放系数。新材料默认1；既有工程保留原值。材料导出限制系数在[0,1]。按用户要求，计算前不再因系数0而弹窗或拦截，显式填写0时按原值计算。

## 旧求解器的按单元兼容

当前部署的 CPU_AUTOCAVE 在 EALL 中先为 IIJX_NAME 追加 `.DAT`，随后 COPY_IIKE 的来源又追加一次，但 EXCAIIWL 按单后缀名读目标。因此只增加一个输入别名不足以解决问题。

`CaveExcavationProtocol::prepareElementInputs` 在独立分析工作区生成：

- 当前最终累计 `IIKE_T01-NN.DAT` 的 `.DAT.DAT` 同内容输入别名。
- CASE01EALL、CASE01JALL 下的单后缀规范输入文件。
- 这两个预建目录的 FLAG_DIR.DAT。旧 NEWDIR 只检查此标记；已有目录没有标记会被误判为创建失败。

UI 当前仅导出 ICASE=1。兼容准备只写输入和目录标记，每次刷新，不改用户源网格、材料或结果。将来替换求解器时，应在 CPU_AUTOCAVE 中移除重复后缀，再整体复核此兼容分支。当前修复没有修改外部 Fortran 源码或二进制。
