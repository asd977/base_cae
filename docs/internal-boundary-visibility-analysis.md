# 网格内部边界不显示问题分析

## 现象
- 导入/划分后，三维网格只显示外表面；内部边界分组存在但不可见。

## 直接原因
当前网格导入逻辑将 **最高维单元**（3D 模型即体单元）插入可视化 `vtkUnstructuredGrid`，而把低维单元（面/线/点）仅用于构建 pick/group 映射，不插入显示网格。

- 在 `loadCurrentGmshMesh` 中，只有 `dim == targetCellDim` 时才执行 `InsertNextCell`。
- `dim < targetCellDim`（例如 3D 模型中的 2D 内部界面）仅写入 `m_mshPickMap.bnd*`，用于选择映射。

因此，渲染时没有真实的 2D 内部单元可画，看到的就只有体网格的外表面。

## 与“之前能显示”的差异点
旧逻辑（你给出的版本）会把不同维度元素都写入同一个 `vtkUnstructuredGrid`，所以内部面可直接作为单元被绘制。

当前实现改为“仅导入目标维度单元 + 低维只建索引”，这会导致：
- 选择/分组信息还在；
- 但内部边界几何未进入显示管线，视觉上消失。

## 次要加重因素
`MeshModuleController::displayCurrentGrid()` 使用 `vtkDataSetMapper` 直接渲染 `nonLineGrid`。当网格里只有体单元时，视觉上天然就是外壳（外表面）而非内部界面。

## 结论
这是导入策略变更引起的回归：
- **不是内部边界“丢了”**，而是它们仅被当作索引数据保存；
- **可视化层缺少可绘制的内部面单元输入**，所以“以前可见、现在不可见”。
